# 영한 번역 (translate-ko)

영어 텍스트를 **자연스러운 한국어**로 번역한다. 직역체가 아닌, 한국어 원어민이 쓴 것처럼 읽히는 결과물을 목표로 한다.

## 입력 처리

사용자 요청에서 번역 대상을 먼저 확정한다.

| 요청 형태 | 처리 |
|---|---|
| 인라인 텍스트 | 대화창에 바로 번역문 출력 |
| 파일 경로 지정 | Read로 읽고, 원문 구조를 유지한 번역본 생성 |
| 여러 파일 / 디렉터리 | Glob으로 목록 확인 후 파일별로 순차 처리 |
| 대상이 불명확 | 무엇을 번역할지 한 번만 되묻는다 |

번역 대상이 100줄을 넘는 파일이면, 결과를 대화에 전부 붙여넣지 말고 파일로 저장한 뒤 저장 위치만 보고한다.

## 출력 규칙 (파일 번역 시)

- 기본은 **원본 옆에 `.ko` 접미사 파일 생성**: `README.md` → `README.ko.md`
- 사용자가 "덮어써", "원본 수정"이라고 명시하면 원본을 직접 수정한다
- 마크다운 구조(제목 레벨, 목록, 표, 코드 블록, 링크), 들여쓰기, 줄바꿈, 프론트매터 키는 **그대로 보존**한다

## 번역 원칙

1. **의미 우선.** 단어 대 단어가 아니라 문장 단위 의미를 옮긴다. 영어의 수동태·관계대명사·긴 명사구는 한국어 어순으로 재구성한다.
   - ✗ "이 함수는 사용자에 의해 제공된 데이터가 검증되는 것을 보장한다"
   - ✓ "이 함수는 사용자가 넘긴 데이터를 검증한다"
2. **문체 일관성.** 문서 전체에서 하나의 어미로 통일한다. 별도 지시가 없으면 기술 문서는 `-다`체(평서형), 사용자 안내문은 `-습니다`체를 쓴다.
3. **어색한 번역투 제거.** "~에 대해서", "~을 가진다", "~되어진다", "~중의 하나이다" 같은 표현을 피한다.
4. **문장부호 현지화.** 영문 따옴표는 한국어 관용에 맞춰 쓰고, 문장 끝 공백·마침표를 한국어 조판에 맞춘다.

## 번역하지 않는 것

다음은 **원문 그대로** 둔다.

- 코드 블록 내부, 인라인 코드(`` `foo()` ``), 명령어, 경로, URL
- 식별자: 변수·함수·클래스·파일명·환경변수·CLI 플래그
- 고유명사와 제품명: `React`, `Docker`, `GitHub`, `Claude Code`
- 라이선스 전문, 저작권 고지

## 기술 용어 처리

정착된 한국어 역어가 있으면 한국어를, 없으면 원어를 그대로 쓴다. 문서에서 **처음 등장할 때만** 병기한다.

- 병기 예: 의존성(dependency), 배포(deployment), 캐시(cache)
- 원어 유지 예: 커밋, 브랜치, 리포지터리, 빌드, 런타임, 프롬프트

한 문서 안에서 같은 용어를 두 가지로 번역하지 않는다. 긴 문서라면 첫 등장 시 정한 역어를 끝까지 유지한다.

## 마무리 보고

번역 후 다음을 한 줄로 보고한다.

- 처리한 파일과 저장 위치
- 판단이 갈렸던 용어가 있으면 선택한 역어와 이유 (최대 3개)
- 원문 자체가 모호해 확신이 낮은 문장이 있으면 해당 위치를 명시
