# 대역 시집 전자책 빌드

영어 원문 txt와 한국어 번역 txt 한 쌍을 받아 EPUB + PDF를 만든다.
시 한 편당 원문 한 쪽, 번역 한 쪽으로 배치한다.

작업 방식과 함정은 `.claude/skills/bilingual-poetry-ebook/SKILL.md`에 정리되어 있다.
**작업 시작 전에 그 파일을 읽는다.**

## 순서

```powershell
.\venv\Scripts\Activate.ps1

python fix_numerals.py <섹션>           # 1. 번호 진단 (미리보기)
python fix_numerals.py <섹션> --write   # 2. 문제가 있으면 적용 (.bak 백업 자동)
python parse_poems.py  <섹션>           # 3. 파싱 — "경고 0건" 확인
python build_epub.py   <섹션>           # 4. EPUB
python build_pdf.py    <섹션>           # 5. PDF
python verify.py       <섹션>           # 6. 검증
```

**3번에서 경고가 남아 있으면 빌드하지 않는다.** 연 구분이 어긋난 책이 만들어진다.
경고 내용을 사용자에게 보고하고, 번역문 행 수를 고쳐야 하는 문제라면 어느 시인지 짚어 멈춘다.

## 판단이 필요한 지점

**번호 수정 적용.** `fix_numerals.py` 미리보기에서 "건너뜀"으로 보고된 줄은 자동 수정 대상이
아니다. 본문일 가능성이 있으니 직접 확인하고, 애매하면 사용자에게 묻는다.

**앞붙임(저자 소개).** `front_matter.py`의 `FIRST_SECTION`에 지정된 권에만 들어간다.
새 섹션을 빌드할 때 이 값을 건드리지 않는다. 사용자가 앞붙임 위치를 바꿔 달라고 할 때만 수정한다.

**쪽 넘침.** 긴 시는 85%까지 줄여 한 쪽에 맞추고, 그래도 안 들어가면 축소 없이 두 쪽에
걸치게 둔다. 이건 정상 동작이므로 보고에 적되 문제로 취급하지 않는다.

**원본 파일.** 번역 txt는 `fix_numerals.py --write`로만 고친다. 직접 편집하지 않는다.
번역 내용(오역·표현)은 사용자가 요청하지 않으면 손대지 않는다.

## 여러 섹션 처리

섹션이 여럿이면 하나씩 끝까지 돌린다. 한 섹션에서 파싱 경고가 나오면 그 섹션만 멈추고
나머지는 계속 진행한 뒤, 마지막 보고에서 어느 섹션이 왜 빠졌는지 밝힌다.

## 보고 형식

```
[<섹션>] 완료
  번호 수정   N곳 (백업: ...bak)        ← 수정이 없었으면 생략
  파싱        시 N편 / N연 · 경고 0건
  EPUB        N KB · 문서 N개
  PDF         N KB · N쪽  (기대 쪽수: 1 + 편수×2 + 앞붙임)
  조판        글자 줄인 시 N개 / 두 쪽에 걸친 시 N개
  검증        통과
```

쪽수가 기대값과 다르면 왜 다른지(두 쪽에 걸친 시, 앞붙임) 설명한다.
검증이 실패하면 어느 항목인지 밝히고, 고치지 못했으면 그 사실을 분명히 적는다.

완료하지 못한 작업을 완료한 것처럼 보고하지 않는다.
