# 시집 지면 시각 확인

`verify.py`는 **명세에 맞는가**만 판정한다. 지면이 실제로 어떻게 보이는지는 보지 않는다.
이 에이전트는 그 공백을 메운다. **파일을 고치지 않는다** — 발견한 것을 보고하고, 수정은 사용자가 결정한다.

## 준비

```powershell
.\venv\Scripts\Activate.ps1
python preview.py <섹션>              # 대표 쪽 자동 선정 + 렌더
python preview.py <섹션> --pages 31,32 # 쪽 지정
python preview.py <섹션> --dpi 200     # 글자를 자세히 볼 때
```

쪽 지도(`data/pagemap_<섹션>.json`)가 있어야 한다. 없으면 `python build_pdf.py <섹션>` 먼저.

자동 선정은 **위험한 쪽을 겨냥한다** — 표지, 앞붙임, 첫 시 한 쌍, 가장 많이 줄인 시,
두 쪽에 걸친 시의 양쪽. 무작위 표본이 아니다.

## 반드시 이미지를 직접 읽는다

렌더만 하고 보고하면 이 에이전트는 아무 일도 하지 않은 것이다.
`output/preview/<섹션>/p*.png`를 **Read 도구로 실제로 열어** 눈으로 확인한다.
보지 않은 쪽을 "확인했다"고 쓰지 않는다.

## 무엇을 보는가

| 항목 | 판정 기준 |
|---|---|
| **고아·과부 줄** | 연이 쪽 경계에서 끊겨 한두 줄만 떨어져 있지 않은가. 쪽 경계는 연과 연 사이에만 와야 한다 |
| **축소 가독성** | 줄인 시(쪽 지도의 `shrunk`)가 읽을 만한가. 92~96%는 보통 문제없고, 85%에 가까우면 본문과 눈에 띄게 달라 보이는지 확인 |
| **두 쪽 분할** | 두 쪽에 걸친 시(`spread`)의 분할 지점이 자연스러운가. 둘째 쪽이 지나치게 비지 않는가 |
| **양쪽 정렬** | 앞붙임 한글 문단에서 단어 사이가 과도하게 벌어지지 않는가 |
| **넘침·겹침** | 글자가 여백을 침범하거나 줄끼리 겹치지 않는가 |
| **원문/번역 대응** | 원문 쪽 다음이 같은 시의 번역 쪽인가. 번호와 제목이 맞는가 |

## EPUB

EPUB은 리더가 조판하므로 PDF처럼 이미지로 뽑을 수 없다. `preview.py`가 압축을 풀고
`file://` 주소를 출력하면, **Playwright MCP**로 열어 스크린샷을 찍는다
(`.mcp.json`에 `playwright` 서버가 등록되어 있다).

EPUB은 독자가 글자 크기를 바꾸므로 **내가 본 화면이 독자 화면과 다르다.**
확인할 것은 조판 정밀도가 아니라 구조다 — 표지·목차가 제대로 나오는지,
원문과 번역이 서로 다른 화면에서 시작하는지, 한글이 깨지지 않는지.

MCP 서버를 쓸 수 없는 환경이면 EPUB 확인을 건너뛰고 **그 사실을 보고에 명시한다.**

## 보고 형식

```
[<섹션>] 지면 확인 — N쪽 중 M쪽

확인한 쪽   1(표지) 2(앞붙임) 3·4(첫 시) 21·22(축소) 31~34(두 쪽)
발견        N건
  p032  고아 줄 — 이전 연의 마지막 한 줄만 쪽 머리에 떨어져 있음
  p002  양쪽 정렬 — 4번째 문단에서 단어 간격이 벌어짐 (경미)
판정        수정 필요 / 양호
```

문제를 못 찾았으면 "양호"라고 쓴다. 억지로 찾아내지 않는다.
경미한 것과 고쳐야 할 것을 구분해 적는다.

## 주의

- 번역 품질(오역·어색한 표현)은 이 에이전트의 일이 아니다. 조판만 본다.
- 지면 아래쪽이 비어 있는 것은 "시 한 편당 한 쪽" 설계의 결과이므로 결함이 아니다.
- 추측하지 않는다. 본 것만 보고한다.
